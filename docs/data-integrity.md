# 数据可靠性

这是整个项目最不能出错的部分。实现集中在两处：

- `src/renderer/src/features/documents/documents.ts` —— 渲染进程，保存调度与冲突判断
- `src/main/services/document/{DocumentService,AtomicWriter,DocumentRecovery}.ts` —— 主进程，落盘与恢复

## 三条硬约束

1. **同一文件的写入必须串行** —— 否则后发的旧任务会覆盖新内容。
2. **写前必须校验磁盘基准版本** —— 否则会静默覆盖其他程序写下的改动。
3. **任何保存失败都不得对外表现为"已保存"** —— 状态机在拿到明确的成功回执前不会回到 `clean`。

## 自动保存：双重节流

```
停止输入 800ms ──► 触发保存
连续输入期间  ──► 最多每 3000ms 必须落盘一次
```

实现见 `SaveController.markDirty()`：第一次置脏时记下时间戳，
之后每次输入都把定时器重排为 `min(800ms, 3000ms - 已连续编辑时长)`。
效果是"打字一停顿就保存"，同时保证长段落连续输入时不会积压太久。

`Ctrl+S` 走 `flush()` 跳过计时立即保存；切换文件、关闭标签页、退出应用同样走 `flush()`。

## 串行与"写后再写"

`flush()` 维护一个 `inFlight` Map：

- 若该文档已有保存在飞，先 `await` 它，结束后**再检查是否仍然脏**，是则再存一轮；
- `runLoop()` 最多循环 20 轮。每轮写入前都会重新取一次编辑器当前文本，
  因此保存期间新敲的内容不会被旧任务覆盖，而是紧接着再写一次。

判定方式：写入前记下 `text`，写完后重新取一次；若不一致说明保存过程中又改了内容，
文档保持 `dirty` 并继续下一轮。

## 原子写入

`AtomicWriter.atomicWriteFile()` 的步骤：

```
同目录临时文件 .<文件名>.<6 字节随机>.mn-tmp
  ├─ 以 'wx' 打开（已存在则失败，避免撞名）
  ├─ 继承原文件权限（新文件用 0644）
  ├─ writeFile → handle.sync()   先落盘，避免掉电后留下空文件
  └─ rename 覆盖目标
最后尽力 fsync 父目录（Windows 上打开目录会失败，忽略即可）
```

临时文件与目标在**同一目录**，保证 rename 是同一文件系统内的原子操作。
目录扫描会跳过 `.mn-tmp` 后缀，避免把自己的中间产物当成笔记；
写入失败时也会主动 unlink 临时文件。

**原子替换不等于防冲突。** 它只能保证"读到的永远是完整内容"，
无法阻止两个程序同时写同一个文件。真正的防线是下一节的版本校验。

## 版本校验与冲突检测

`document:save` 的入参包含 `baseHash` —— 读取该文件时磁盘内容的哈希。
主进程在写入前比对当前磁盘哈希：

| 情况 | 结果 |
| --- | --- |
| 与 `baseHash` 一致 | 正常写入，返回新哈希与新 mtime |
| 不一致 | 返回 `CONFLICT` 及磁盘侧哈希、mtime，**拒绝写入** |

渲染进程据此把文档置为 `conflict` 并停止一切自动保存。
冲突状态下必须由用户显式选择：

- **用编辑器内容覆盖** —— `force: true`，此时 `baseHash` 传空串
- **重新加载磁盘版本** —— 丢弃编辑器内容，采用磁盘版本

冲突提示不会自己消失，也不会被自动保存悄悄"解决"。

## 外部修改检测

`FileWatcher` 监听工作区变化，`document:externalChange` 到达渲染进程后按序判断：

1. **忽略自身回声** —— 刚写入后 1500ms 内的文件事件直接丢弃（我们自己写盘也会触发 watcher）。
2. 读取当前磁盘内容，若哈希**等于**记录的 `baseHash`，说明只是一次回声，忽略。
3. 若文档正 `dirty` / `saving` → 置为 `conflict`，记下磁盘侧哈希与 mtime。
4. 否则编辑器是干净的 → 静默采用磁盘内容，提示"已从磁盘更新"。

文件被外部**删除**时：脏文档置为 `missing` 并保留内容等用户决定；
干净文档直接关闭标签页并提示。

## 保存失败的分类处置

| 失败原因 | 处理 |
| --- | --- |
| `CONFLICT` | 置为 `conflict`，等待用户选择 |
| `NOT_FOUND` | 置为 `missing`（文件被外部删除 / 移动） |
| `PERMISSION_DENIED` / `DISK_FULL` / `IO_ERROR` | 置为 `error` 并**退避重试** |
| `TOO_LARGE` / `OUTSIDE_WORKSPACE` / `INVALID_NAME` | 置为 `error`，不重试 |

退避策略：`min(1000ms × 2^(n-1), 8000ms)`，最多 4 次。
重试耗尽后停在 `error` 等用户手动保存；用户在 `error` 状态下继续编辑会清掉报错文案，
下次输入重新走一遍保存流程。

## 格式保真

读取时记录原文件的**换行风格**（`\n` / `\r\n`）与**是否带 BOM**，保存时按原样还原 ——
编辑器内部统一用 LF，只在落盘时还原。这两个字段随文档元信息在 IPC 上传递（`eol`、`hasBom`）。

预览不支持某种语法时，源文本一字不改。

## 关闭握手

关闭窗口不是"直接退出"，而是一次三阶段确认：

```
用户点关闭
 └─ 主进程取消默认关闭，向渲染进程发 app:requestClose（5 秒超时）
      └─ 渲染进程 flushAll()：把所有脏文档立刻写一遍（最多等 3 秒）
           ├─ 全部成功 → 回 { allSaved: true } → 主进程放行关闭
           └─ 仍有未保存 → 回 { allSaved: false, drafts: [...] }
                └─ 主进程弹原生对话框：取消 / 保存草稿并退出 / 丢弃更改并退出
```

**任何情况下都不会静默丢弃未保存内容。**

## 崩溃恢复草稿

选择"保存草稿并退出"后，未保存的正文写入 `userData/recovery`，
下次打开同一工作区时通过 `draft:available` 提示恢复。

草稿是**旁路**机制：它不写入用户的笔记文件，只在正常保存路径失败时兜底。

## 关闭标签页

只要文档处于 `dirty` / `error` / `saving` / `missing` / `conflict` 任一状态，
关闭标签页都会先弹对话框让用户选择「保存并关闭 / 放弃更改 / 取消」，
且**保存失败时保持标签页打开**（提示"保存未成功"），而不是关掉让内容消失。
